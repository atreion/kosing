# Skills and Data Repo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the valuator its three AI roles: a `DATA_PATH`-aware CLI (`kosing where`, `kosing value <ID>`), a private `kosing-data` repo seeded with copies of the standing documents and theses, and four skills (researcher, analyst, advisor, orchestrator), proved by one real company run end to end.

**Architecture:** `src/data-path.ts` is pure: it resolves `DATA_PATH` from an environment map and the text of `.env`, parses company ids and builds company paths. `src/cli.ts` gains the two company-level forms and is still the only file that touches the filesystem, now also writing `results.json`. The skills are Markdown in `.claude/skills/`, run with this repo as the working directory, and reach the data repo only through `kosing where`.

**Tech Stack:** TypeScript 7, Node 22.18+ (`util.parseEnv`, `node:path`), tsx, `node:test`, Biome. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-10-skills-design.md`

**Execution:** Claude implements every task inline (superpowers:executing-plans). Checkpoints: after Task 2 (the CLI), after Task 7 (the data repo and all four skills), after Task 8 (the end-to-end run). Task 8 starts by asking the user which company to run.

## Global Constraints

- Node `>=22.18`. TypeScript strict settings in `tsconfig.json` stay as they are.
- Relative imports carry `.ts`. Filenames kebab-case. Tests are `*.test.ts` next to the code, `node:test` + `node:assert/strict`.
- `npm run check` passes before every commit in this repo.
- No `as` casts in `src/` outside the two brand transforms and the test utilities.

- The variable is `DATA_PATH`. No default value anywhere in code.
- The company id is `<TICKER>.<EXCHANGE>`, split at the last dot.
- Skills never push any repo. Skills commit only in the data repo, only the documents they wrote.
- Skill names are gerunds. "Kosing" is capitalized in prose; `kosing` only in code, commands and paths.
- Never write the user's real name or a machine-specific absolute path into a committed file in this repo. `$HOME` in a shell command is fine.
- Commits in this repo go directly on `main`.

## Rulings made while planning

- **`resolveDataPath` parses `.env` text with `util.parseEnv` instead of calling `process.loadEnvFile`.** Probed on Node 22.22: `loadEnvFile` lets an existing variable win, as the spec wants, but it mutates `process.env`, which makes the resolver untestable without global state. Reading the file stays in `src/cli.ts`'s entry block; the resolver takes the text.
- **`.env` is located from `src/cli.ts`'s own URL (`../.env`), so it is the repo root.** Matches the spec. A missing file is `null`; any other read error is thrown, not hidden.
- **An empty `DATA_PATH=` counts as unset**, in the environment and in the file, so an empty override does not mask the file's value.
- **`DATA_PATH` must be absolute.** The spec says "an absolute path"; a relative one would resolve against whatever directory a skill happened to run in. Rejected with its own message.
- **The `DATA_PATH=<path>` echo goes to stderr on `where <ID>` and `value <ID>` only.** Bare `kosing where` prints the path on stdout already.
- **The id mismatch check runs after decode succeeds**, reading the ticker and exchange from the decoded company, and is reported as a `DecodeError` with rule `semantic.companyIdMismatch` at path `company`. Decode errors in the facts come first; a mismatch is only meaningful for facts that decode.
- **The id's ticker may not start with a dot**, besides the spec's rules (non-empty, no `/`, `\`, whitespace or `..`). `.STO` would otherwise name a hidden directory.
- **`kosing-data` is created at `$HOME/personal/kosing-data`**, following the user's convention for personal projects, and this repo's git-ignored `.env` points at it. The user creates the private remote.
- **`SOURCE_REGISTRY.md` is copied into the researcher's references with three wording edits** so it names `facts.json` fields instead of dossier fields. Everything else in it is generic.
- **The four skills are written in full here, not sketched.** They are the deliverable; a placeholder in a skill is a placeholder in the product.

## Review Focus

1. **A `DATA_PATH` inherited from another tool's environment.** The user must see which directory Kosing used. Every id-level command echoes `DATA_PATH=<path>` on stderr. (Task 2)
2. **An id that walks out of the data repo**, such as `../x.STO` or `a/b.STO`. Rejected as a usage error before any path is built. (Task 1)
3. **A company directory that exists without `facts.json`.** Exit 1 with `file.unreadable` naming the facts, and no `results.json` written. (Task 2)
4. **A failed run with an earlier `results.json` present.** The earlier file is left byte for byte. (Task 2)
5. **`DATA_PATH` set to a relative path, or to a directory that does not exist.** Exit 2 with a message naming the variable. (Tasks 1 and 2)

```ts
/**
 * Where the data repo is, and where one company's documents live in it.
 * Pure: the caller reads the environment and the .env file and passes them
 * in, which is what lets the tests cover precedence without touching
 * process.env.
 */

import { isAbsolute, join } from "node:path";
import { parseEnv } from "node:util";

export const DATA_PATH_KEY = "DATA_PATH";

export type CompanyId = {
  readonly ticker: string;
  readonly exchange: string;
  /** The id as written, which is also the directory name. */
  readonly text: string;
};

const EXCHANGE = /^[A-Z0-9]+$/;
const UNSAFE_IN_TICKER = /[\s/\\]/;

/** Splits at the last dot, so BRK.B.NYSE is ticker BRK.B on NYSE. */
export function parseCompanyId(text: string): CompanyId | null {
  const dot = text.lastIndexOf(".");
  if (dot <= 0) return null;
  const ticker = text.slice(0, dot);
  const exchange = text.slice(dot + 1);
  if (!EXCHANGE.test(exchange)) return null;
  if (UNSAFE_IN_TICKER.test(ticker) || ticker.includes("..") || ticker.startsWith(".")) {
    return null;
  }
  return { ticker, exchange, text };
}

export type DataPath =
  | { readonly ok: true; readonly path: string }
  | {
      readonly ok: false;
      readonly reason: "unset" | "notAbsolute" | "notADirectory";
      readonly message: string;
    };

function nonEmpty(value: unknown): string | undefined {
  return typeof value === "string" && value !== "" ? value : undefined;
}

/** parseEnv is typed loosely across Node versions; reading through entries keeps it honest. */
function fromEnvFile(text: string | null): string | undefined {
  if (text === null) return undefined;
  const entry = Object.entries(parseEnv(text)).find(([key]) => key === DATA_PATH_KEY);
  return nonEmpty(entry?.[1]);
}

export function resolveDataPath(
  env: Readonly<Record<string, string | undefined>>,
  envFileText: string | null,
  isDirectory: (path: string) => boolean,
): DataPath {
  const value = nonEmpty(env[DATA_PATH_KEY]) ?? fromEnvFile(envFileText);
  if (value === undefined) {
    return {
      ok: false,
      reason: "unset",
      message: `${DATA_PATH_KEY} is not set. Set it in the environment or in .env at the Kosing repo root; see .env.example.`,
    };
  }
  if (!isAbsolute(value)) {
    return {
      ok: false,
      reason: "notAbsolute",
      message: `${DATA_PATH_KEY} must be an absolute path, got ${value}`,
    };
  }
  if (!isDirectory(value)) {
    return {
      ok: false,
      reason: "notADirectory",
      message: `${DATA_PATH_KEY} is ${value}, which is not a directory`,
    };
  }
  return { ok: true, path: value };
}

export function companyDir(dataPath: string, id: CompanyId): string {
  return join(dataPath, "companies", id.text);
}
```

```ts
type CaptureOptions = {
  readonly env?: Readonly<Record<string, string | undefined>>;
  readonly envFile?: string | null;
  readonly dirs?: readonly string[];
};

function capture(files: Record<string, string> = {}, options: CaptureOptions = {}) {
  const out: string[] = [];
  const err: string[] = [];
  const fs: Record<string, string> = { ...files };
  return {
    io: {
      stdout: (s: string) => out.push(s),
      stderr: (s: string) => err.push(s),
      readFile: (path: string) => {
        const text = fs[path];
        if (text === undefined) throw new Error(`ENOENT: ${path}`);
        return text;
      },
      env: options.env ?? {},
      envFile: options.envFile ?? null,
      isDirectory: (path: string) => (options.dirs ?? []).includes(path),
      fileExists: (path: string) => path in fs,
      writeFile: (path: string, text: string) => {
        fs[path] = text;
      },
    },
    out,
    err,
    fs,
  };
}
```

```ts
const USAGE = `usage:

  kosing value --facts F [--case C]   results.json on stdout, exit 0; DecodeError[] on stderr, exit 1

function isDocument(name: string | undefined): name is "facts" | "case" {
  return name === "facts" || name === "case";
}

type ValueArgs = { readonly facts: string; readonly investmentCase: string | null };

function parseValueArgs(rest: readonly string[]): ValueArgs | null {
  let facts: string | null = null;
  let investmentCase: string | null = null;
  for (let i = 0; i < rest.length; i += 2) {
    const flag = rest[i];
    const path = rest[i + 1];
    if (path === undefined) return null;
    if (flag === "--facts") facts = path;
    else if (flag === "--case") investmentCase = path;
    else return null;
  }
  return facts === null ? null : { facts, investmentCase };
}

type Loaded =
  | { readonly ok: true; readonly json: unknown }
  | { readonly ok: false; readonly error: DecodeError };

function fileError(file: DecodeError["file"], rule: string, text: string): DecodeError {
  return { file, layer: "schema", rule, path: "", message: text };
}

function message(e: unknown): string {
  return e instanceof Error ? e.message : String(e);
}

function loadJson(io: CliIo, file: DecodeError["file"], path: string): Loaded {
  let text: string;
  try {
    text = io.readFile(path);
  } catch (e) {
    return { ok: false, error: fileError(file, "file.unreadable", `${path}: ${message(e)}`) };
  }
  try {
    return { ok: true, json: JSON.parse(text) };
  } catch (e) {
    return { ok: false, error: fileError(file, "json.invalid", `${path}: ${message(e)}`) };
  }
}

type Evaluated =
  | { readonly ok: true; readonly results: Results }
  | { readonly ok: false; readonly errors: readonly DecodeError[] };

function evaluate(args: ValueArgs, io: CliIo): Evaluated {
  const facts = loadJson(io, "facts", args.facts);
  const investmentCase =
    args.investmentCase === null ? null : loadJson(io, "case", args.investmentCase);
  const loadErrors = [facts, investmentCase].flatMap((l) => (l !== null && !l.ok ? [l.error] : []));
  if (!facts.ok || (investmentCase !== null && !investmentCase.ok)) {
    return { ok: false, errors: loadErrors };
  }
  const result = valuate(facts.json, investmentCase === null ? undefined : investmentCase.json);
  return result.success ? { ok: true, results: result.data } : { ok: false, errors: result.error };
}

function reportErrors(io: CliIo, errors: readonly DecodeError[]): number {
  io.stderr(`${JSON.stringify(errors, null, 2)}\n`);
  return 1;
}

function runValueFiles(args: ValueArgs, io: CliIo): number {
  const evaluated = evaluate(args, io);
  if (!evaluated.ok) return reportErrors(io, evaluated.errors);
  io.stdout(`${JSON.stringify(evaluated.results, null, 2)}\n`);
  return 0;
}

/** Resolves DATA_PATH, or reports why not. Exit 2 is the caller's. */
function dataPath(io: CliIo, echo: boolean): string | null {
  const resolved = resolveDataPath(io.env, io.envFile, io.isDirectory);
  if (!resolved.ok) {
    io.stderr(`${resolved.message}\n`);
    return null;
  }
  if (echo) io.stderr(`DATA_PATH=${resolved.path}\n`);
  return resolved.path;
}

/** A directory renamed by hand must not price the wrong company. */
function checkCompanyId(id: CompanyId, results: Results): readonly DecodeError[] {
  const { ticker, exchange } = results.inputs.company.identity;
  if (ticker === id.ticker && exchange === id.exchange) return [];
  return [
    {
      file: "facts",
      layer: "semantic",
      rule: "semantic.companyIdMismatch",
      path: "company",
      message: `directory is ${id.text}, facts are for ${ticker}.${exchange}`,
    },
  ];
}

function runValueId(id: CompanyId, io: CliIo): number {
  const data = dataPath(io, true);
  if (data === null) return 2;
  const dir = companyDir(data, id);
  const casePath = join(dir, "case.json");
  const evaluated = evaluate(
    { facts: join(dir, "facts.json"), investmentCase: io.fileExists(casePath) ? casePath : null },
    io,
  );
  if (!evaluated.ok) return reportErrors(io, evaluated.errors);
  const mismatch = checkCompanyId(id, evaluated.results);
  if (mismatch.length > 0) return reportErrors(io, mismatch);
  const out = join(dir, "results.json");
  io.writeFile(out, `${JSON.stringify(evaluated.results, null, 2)}\n`);
  io.stdout(`${out}\n`);
  return 0;
}

function usage(io: CliIo): number {
  io.stderr(USAGE);
  return 2;
}

function runWhere(rest: readonly string[], io: CliIo): number {
  if (rest.length === 0) {
    const data = dataPath(io, false);
    if (data === null) return 2;
    io.stdout(`${data}\n`);
    return 0;
  }
  const id = rest.length === 1 && rest[0] !== undefined ? parseCompanyId(rest[0]) : null;
  if (id === null) return usage(io);
  const data = dataPath(io, true);
  if (data === null) return 2;
  io.stdout(`${companyDir(data, id)}\n`);
  return 0;
}

function runValue(rest: readonly string[], io: CliIo): number {
  const [first] = rest;
  if (rest.length === 1 && first !== undefined && !first.startsWith("--")) {
    const id = parseCompanyId(first);
    return id === null ? usage(io) : runValueId(id, io);
  }
  const args = parseValueArgs(rest);
  return args === null ? usage(io) : runValueFiles(args, io);
}

export function runCli(argv: readonly string[], io: CliIo): number {
  const [command, ...rest] = argv;
  if (command === "schema" && isDocument(rest[0]) && rest.length === 1) {
    io.stdout(`${JSON.stringify(emitJsonSchema(rest[0]), null, 2)}\n`);
    return 0;
  }
  if (command === "value") return runValue(rest, io);
  if (command === "where") return runWhere(rest, io);
  return usage(io);
}

/**
 * Whether this module is the process entry point. import.meta.url is
 * percent-encoded, so the path from argv has to go through pathToFileURL
 * rather than a template string, or a directory with a space never matches.
 */
export function isMain(importMetaUrl: string, argv1: string | undefined): boolean {
  return argv1 !== undefined && importMetaUrl === pathToFileURL(argv1).href;
}

/** .env at the repo root, found from this file rather than the working directory. */
function readEnvFile(): string | null {
  try {
    return readFileSync(new URL("../.env", import.meta.url), "utf8");
  } catch (e) {
    if (e instanceof Error && "code" in e && e.code === "ENOENT") return null;
    throw e;
  }
}

if (isMain(import.meta.url, process.argv[1])) {
  process.exitCode = runCli(process.argv.slice(2), {
    stdout: (text) => process.stdout.write(text),
    stderr: (text) => process.stderr.write(text),
    readFile: (path) => readFileSync(path, "utf8"),
    env: process.env,
    envFile: readEnvFile(),
    isDirectory: (path) => existsSync(path) && statSync(path).isDirectory(),
    fileExists: (path) => existsSync(path),
    writeFile: (path, text) => writeFileSync(path, text),
  });
}
```

````markdown
# Researching Company

Write one company's `facts.json` and `research.md` in the data repo. This is
the only skill that does web research feeding a company's documents. It
records what is observable and what the company is; it never values,
recommends, or judges whether to own it.

## Start here

Run every command from the Kosing repo root. Read before searching or writing:

- `references/researcher-brief.md`: units, signs, cost of capital, FX, the source hierarchy, the AI-cycle exposure levels, and what never goes in.
- `references/source-registry.md`: where to look, per market.

## Workflow

1. **Name the company.** Settle the ticker and exchange as the exchange quotes
   them. The id is `TICKER.EXCHANGE`, for example `ACME.STO` or `BRK.B.NYSE`.
   Run `npm run --silent kosing -- where <ID>`. It prints the company's
   directory. An error naming `DATA_PATH` means the data repo is not
   configured: stop and say so. If the directory exists, this is a refresh
   (see Refreshes); otherwise create it with `mkdir -p`.
2. **Read the contract.** Run `npm run --silent kosing -- schema facts`. Field
   names, types, enums and required keys come from it, not from memory. These
   rules are not in the schema, and decode enforces them:
   - every `sourceRef` and every member of every `sourceRefs` is an id in
     `sources`, and source ids are unique;
   - `financials.fiscalYears[].fy` values are distinct;
   - `costOfCapital.equityWeight + costOfCapital.debtWeight` is 1;
   - when `market.priceCurrency` differs from `currency`, `fx.spotRates` has
     that pair in either direction;
   - the share count decode uses (`market.sharesDilutedM`, or
     `market.sharesOutstandingM` when diluted is null) is not 0.
3. **Write `facts.json`.** Every key is present. Anything unknown is `null`
   and also gets a `gaps` entry with the field's path and the reason. Every
   figure cites a source by id. Units and signs follow the brief.
4. **Write `research.md`** with exactly these sections, citing the same `S`
   ids as the facts inline:
   - `## What the business does`: products, customers, how it makes money, segments.
   - `## Moat and competition`
   - `## Management, ownership and governance`
   - `## Customers and revenue quality`: concentration, recurring share, contract length where reported.
   - `## Risks`
   - `## AI-cycle exposure`: the first line is exactly `Level: <level>`, one
     of `direct`, `picks_and_shovels`, `wealth_effect`, `disruption`,
     `second_order_only` (defined in the brief), followed by the revenue share
     or customer concentration behind it. Required for every company.
     `second_order_only` is a valid, sourced answer; omitting the section is not.
   - `## Source conflicts`: each conflict, the competing values, which one went
     into the facts and why. `None.` when there were none.
5. **Validate by screening.** Run `npm run --silent kosing -- value <ID>`.
   Exit 0 writes `results.json`: that is the screen, and it means the facts
   decode. Exit 1 prints `DecodeError[]` as JSON: fix `facts.json` at each
   `path` and run again. Never weaken or invent a figure to get past an error.
   If the honest answer is unknown, it is `null` with a gap.
6. **Commit in the data repo**, only the files this skill wrote:

   ```
   D="$(npm run --silent kosing -- where <ID>)"
   git -C "$D" add facts.json research.md results.json
   git -C "$D" commit -m "research(<ID>): <created|price|quarterly|annual|governance> as of <facts asOf>"
   ```

   Never push.
7. **Report**: created or refreshed, the facts' `asOf`, the gaps, the source
   conflicts, and the resolutions in `results.json` (the fallbacks decode
   applied). Hand off to `building-case`. No valuation figures and no opinion
   on the price.

## Refreshes

Read the existing `facts.json` and `research.md` first. Change only what the
scope covers, set `asOf` to today, and keep every other value and its source.

| Scope | Changes |
| --- | --- |
| `price` | `market`, `fx.spotRates` |
| `quarterly` | `financials.ltm`, `financials.quarters`, `market`, `estimates`, `fx.spotRates` |
| `annual` | a new `financials.fiscalYears` row, `balanceSheet`, `costOfCapital`, `historicalRanges`, `peers`, and everything `quarterly` covers |
| `governance` | the `## Management, ownership and governance` section of `research.md` only |

New figures get new source ids with today's `retrieved` date; never reuse an
old id for a new retrieval. Remove a source only when nothing cites it any
more. Git history is the revision log.

## Boundaries

- No verdicts, recommendations, target prices or entry prices. No WACC, DCF,
  margins or growth rates computed by hand: `kosing value` computes them.
- No `case.json`. Classification and assumptions belong to `building-case`.
- If web access is unavailable, say so and stop. Never present remembered
  figures as researched ones.
- Never write to `../invest`.
````

````markdown
# Researcher brief

What goes into `facts.json` and `research.md`, and what never does. The schema
from `kosing schema facts` is authoritative on shape; this brief is
authoritative on meaning.

## Units and signs

- `currency` is the reporting currency. `unit` (`millions`, `thousands`,
  `ones`) applies to every aggregate figure: financial rows, the balance sheet,
  holdings, estimates of revenue and EBIT. Use the unit the source reports in;
  decode rescales.
- Per-share figures are never scaled by `unit`. Quoted ones (`market.price`,
  the 52-week range, `historicalRanges.sharePrice`) are in
  `market.priceCurrency`, the currency the exchange quotes. Reported ones
  (`estimates[].eps`) are in `currency`.
- Share counts are millions, whatever `unit` says.
- Percentages are fractions: `0.21`, not `21`.
- Figures keep the sign the statements give them: `capex`, `dividendsPaid`,
  `interestExpense` and `taxExpense` are negative when they are outflows.
- `totalDebt` is interest-bearing debt. Operating leases and pensions have
  their own fields and stay out of `totalDebt`.
- `totalEquity` is book equity attributable to shareholders.
- `ltm` is the trailing twelve months to the latest reported quarter. Leave it
  null when the company does not report quarters.

## Cost of capital

- `riskFreeRate`: the 10-year government bond yield in the reporting currency;
  `riskFreeBasis` says which bond and when.
- `erp` and `countryPremium` from Damodaran's current country table;
  `countryPremium` is null when the table shows none.
- **Sanity-check the beta before recording it.** After a large
  narrative-driven derating, measured 5-year regression betas are often
  artifacts (observed twice on large European compounders in August 2026:
  0.35 and 0.19). A beta that prices the cost of equity below the company's
  own bond coupon is implausible. Cross-check against Damodaran's sector beta.
  When the measured beta fails, set `betaCompany` to null and `betaSector` to
  the sector figure, so decode records the substitution, and write both values
  under `## Source conflicts`.
- `taxRateEffective` from the latest annual report; `taxRateStatutory` is the
  country's corporate rate.
- `equityWeight` and `debtWeight` at market values on `weightsAsOf`: market
  capitalisation against total debt.

## FX

`market.priceCurrency` differs from `currency` only when the shares are quoted
in a currency the company does not report in. Then `fx.spotRates` carries that
pair, in either direction, dated and sourced. `fx.exposures` lists each
currency with a material share of revenue or costs, with the shares the
company reports; an unreported share is null. `fx` is null for a company with
one currency and no material foreign exposure.

## Source hierarchy

When sources conflict on a figure, prefer, in order:

1. The most recent primary filing (annual, interim or quarterly report) from
   the company's IR page or the regulator.
2. An older primary filing.
3. Broker estimate pages and consensus.
4. Aggregator pages.

Set `tier` to `primary`, `secondary` or `tertiary` accordingly. Use the
highest-tier value and record the conflict in `research.md` under
`## Source conflicts`.

Source ids are `S1`, `S2`, … in order of first use. One id is one document
retrieved once.

## AI-cycle exposure levels

The level is the first line of `## AI-cycle exposure` in `research.md`:
`Level: <level>`. The advisor keys the required-discount add-on on it, so it
is a structured line, not a sentence buried in the risks.

- `direct`: revenue depends on AI compute demand or AI model economics. Chip
  vendors, hyperscalers, model labs, neoclouds.
- `picks_and_shovels`: a material revenue share from datacentre capex. Power,
  grid, cooling, construction, semicap, cabling.
- `wealth_effect`: demand driven by customers' financial-asset gains. Luxury,
  premium autos, brokers, high-end housing.
- `disruption`: AI substitutes for the product or compresses its pricing.
  Seat-priced software, IT services, media, education.
- `second_order_only`: exposed through the general recession channel only.
  Consumer staples, domestic utilities, most insurers, defence. Not zero
  exposure, just the weakest channel.

Cite the revenue share or customer concentration behind the level.

## What never goes in

- Computed metrics: margins, growth rates, ROIC, FCF conversion, multiples.
  `kosing value` computes them.
- Valuation outputs: WACC, DCF, reverse DCF, target or entry prices, margins of
  safety.
- Recommendations: action, position size, broker, wrapper.
- Verdict-shaped sentences in `research.md`: "the company has a wide moat",
  "management is strong", "FX exposure is immaterial", "the stock is cheap".
  Describe what is observable and cite it. Judging it is the advisor's work.
````

````markdown
   and why, commit nothing, and stop. The advisor reads a missing case as too

3. **Find the theses.** Read only each thesis file's front matter and title:

   ```
   for f in "$DATA"/theses/*.thesis.md; do
     awk 'NR==1 && /^---$/ {fm=1; next} fm && /^---$/ {fm=0; next} fm || /^# / {print} /^# / {exit}' "$f"
     echo
   done
   ```

   Cite a thesis by `slug` only when its `status` is `hardened`, its
   `last_tested` is within the last twelve months, and the case genuinely rests
   on it. Never open a thesis body: a case that reads the argument for its own
   thesis is grading itself. `theses` may be empty.
4. **Write `case.json`** against `npm run --silent kosing -- schema case`.
   - `ticker` equals the facts' `company.ticker`; `factsAsOf` equals the
     facts' `asOf`.
   - Every `sourceRefs` id is already in the facts' `sources`. When an
     assumption needs a source the facts do not have, hand back to
     `researching-company` naming what is needed. Never cite an absent source.
   - `rationale` says what the base case assumes and why, including the weight
     given to management guidance. For `dcf`, `terminal.basis` argues the
     terminal figure for this company.
   - `overrides` stay null unless there is a reason, which goes in
     `overrides.rationale`. A WACC override is a rate strictly between 0 and 1.
   - `sensitivity` stays null unless a different grid is needed.

   Rules the schema cannot show, which decode enforces: scenario triples are
   ordered `bear <= base <= bull`; no scenario multiple exceeds
   `multipleCeiling` when it is set; overrides and sensitivity are allowed for
   `dcf` only, and sensitivity steps each include 0.
5. **Run `kosing value <ID>` once.** On exit 1, fix `case.json` at each `path`
   (or hand back for a `facts` error) and run again. Then read
   `results.json`. Changing an assumption after seeing the value needs a
   reason written into `rationale`, such as an error found or a fact misread.
   Moving an assumption toward the price is tuning, and is not allowed.
6. **Sanity-check, without a verdict.** Look at `valuation.terminalValuePctOfEv`
   (above 0.75 needs the terminal argument to carry the case), the
   resolutions (`dcfUnavailable`, `dcfBasePeriodFromFiscalYear`, and others),
   the spread of the sensitivity grid, and the multiples against their bands.
   Record concerns in `rationale` and run `kosing value <ID>` again so
   `results.json` matches the committed case.
7. **Commit in the data repo:**

   ```
   git -C "$D" add case.json results.json
   git -C "$D" commit -m "case(<ID>): <method>, <classification>"
   ```

   Never push.
8. **Report** the classification, the method, the theses cited, the key
   assumptions, and the sanity checks. No buy, pass or price opinion. Hand off
   to `advising-on-company`.

## When to rewrite a case

The research changes the story; a cited thesis is falsified, retired, or goes
untested for twelve months; or `results.json` carries a `casePredatesFacts`
warning and the assumptions are affected by what changed. A price refresh
alone does not touch the case.

## Boundaries

- No web research. Never edit `facts.json` or `research.md`.
- No verdict, no required discount, no entry price.
- Never open a thesis body.
- Never write to `../invest`.
````

````markdown
# The base case

The base case is the honest central estimate: defensible, sourced, neither
promotional nor punitive. It is what you actually believe the business does,
not a number pre-discounted for safety. The margin of safety is applied
separately and visibly by the advisor, as a required discount from this value,
so discounting the inputs as well double-counts and hides how large the real
margin is.

- **Management guidance is admissible evidence**, weighted by the company's
  delivery record. Checklist question G3 ("what did management promise five
  years ago, and what happened") is the test. Say in `rationale` what weight
  you gave it and why. Ignoring guidance wholesale replaces one judgement with
  another and calls the substitution conservative.
- **Argue terminal growth for this company** in `terminal.basis`, and never
  default it. Terminal value routinely runs 65 to 85 percent of the total, so
  that single figure is most of the valuation. When `results.json` shows
  `terminalValuePctOfEv` above 0.65, say so in the basis and justify the
  figure specifically.
- **Credit a serial acquirer's redeployment engine** where the filed record
  shows capital deployed at returns above the cost of capital. Charge the
  acquisitions needed to replace decaying units as capex and credit the
  return. Charging the capital while crediting nothing is not conservatism; it
  is an error.
- **Derive the fade curve; do not copy it.** The growth and margin paths are
  ten numbers each because the company's path is its own. If two cases written
  in one sweep end up with the same curve shape, say why in `rationale`.
- **The one case for anchoring low:** a levered serial acquirer with a weak
  organic record and acquisition-fuelled reported growth. Anchor on the filed
  organic record there. That is a judgement about a business shape, not a
  general posture.

For `normalisedEarnings`: take the margin range from the reported margin
history and name the years behind it in `rationale`; take the EV/EBIT range
from peers in the facts or a cited sector table; use `multipleCeiling` as your
own guard against paying a peak-cycle multiple.

For `nav`: `warrantedDiscount` is the discount the market has historically
applied to this company's reported NAV, sourced, and argued in `rationale` if
you depart from it.
````

````markdown
# Advising on Company

Read one company's documents and the investor's standing documents, and write
`advice.md`. The advisor does no web research and never edits facts or case.
Passing is a normal outcome.

## Start here

Run every command from the Kosing repo root.

```
DATA="$(npm run --silent kosing -- where)"
D="$(npm run --silent kosing -- where <ID>)"
```

Read:

- `$DATA/standing/INVESTMENT_WISDOM.md`, including the required-discount table under "Margin of safety".
- `$DATA/standing/INVESTMENT_CHECKLIST.md`
- `$DATA/standing/MARKET_OUTLOOK.md`
- `$DATA/standing/FX_CONTEXT.md`
- `$D/facts.json`, `$D/research.md`, `$D/case.json` if present.

## Workflow

1. **Freshness.** Run `npm run --silent kosing -- value <ID>`. On exit 1,
   stop: hand a `facts` error to `researching-company` and a `case` error to
   `building-case`. Never read `results.json` after a failed run; it is stale.
   Then read `$D/results.json`, every resolution and every warning. A
   `casePredatesFacts` warning is stated first: the case may not reflect the
   current facts.
2. **Checklist.** Answer every applicable question in the checklist from the
   documents and results. List each failed or unanswerable question by id. An
   unanswerable applicable question is a data gap, and it weighs toward pass or
   too hard.
3. **Required discount, with the working shown.**
   - The classification's discount comes from the wisdom table. Its keys are
     snake_case; map them to Kosing's: `quality_compounder` is
     `qualityCompounder`, `garp` is `garp`, `holding_company` is
     `holdingCompany`, `special_situation` is `specialSituation`,
     `value_cyclical` is `valueCyclical`. Say that you mapped them.
   - Add the add-on for the `Level:` line under `## AI-cycle exposure` in
     `research.md`. If that line is missing, say so: the hurdle cannot be
     stated, and the name goes back to `researching-company`.
   - The base value is `valuation.valuePerShare` for `dcf` and `nav`, and
     `valuation.scenarios.base.valuePerShare` for `normalisedEarnings`. It is
     in the reporting currency.
   - Entry price = base value × (1 − required discount). Compare it with
     `inputs.company.market.price`, also in the reporting currency. When the
     facts' `market.priceCurrency` differs, also state the entry price in the
     trading currency, converting with the rate in the
     `priceConvertedToReporting` resolution (divide by the rate when
     `inverted` is false, multiply when it is true).
   - With no case, or `valuation: null`, there is no base value. Say so, name
     the resolution that explains it, and do not count it as a failure.
4. **Wisdom and outlook.** Apply them. Write the four-sentence idea a
   ten-year-old could follow. If an honest four sentences cannot be written,
   the verdict is `tooHard`.
5. **Decide.** One of `watching`, `accumulate`, `pass`, `tooHard`, with a
   conviction of `low`, `medium` or `high`.
   - A price that does not clear the required discount bars `accumulate`
     unless an override reason is written in `advice.md`. Never override
     silently.
   - Clearing it compels nothing. The checklist and the four-sentence test
     still govern, and a failed applicable question still stops the name.
   - A `pass` names the failed question, or how far the price missed the
     entry price.
6. **Write `$D/advice.md`** with these headings, in this order:

   ```

   ## The idea in four sentences
   ## Verdict

   ## Checklist
   <failed and unanswerable questions by id, each with one line>
   ## What the numbers say

   ## What would change the verdict
````
